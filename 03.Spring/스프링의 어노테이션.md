스프링에서 어노테이션(@Annotation)은 단순히 주석처럼 보이지만
, 실제로는 **[[리플랙션| 반사(Reflection)]]와 프록시(Proxy)** 라는 강력한 자바 기술을 통해 동작합니다.


### 스프링 어노테이션의 동작 과정
##### 1단계: 컴포넌트 스캔 (Component Scan)
애플리케이션이 실행될 때, 스프링은 특정 패키지 내의 클래스들을 훑으며 어노테이션이 붙은 클래스들을 찾아냅니다.
- `@Component`, `@Service`, `@Repository`, `@Controller` 등이 그 대상입니다.
##### 2단계: 리플렉션 (Reflection)을 통한 분석
스프링의 `BeanFactory`나 `ApplicationContext`는 자바의 **Reflection API**를 사용하여 런타임에 클래스의 정보를 분석합니다.
- "이 클래스에 어떤 어노테이션이 붙어 있지?"
- "의존성 주입(`@Autowired`)이 필요한 필드가 어디지?" 를 파악하고 인스턴스를 생성하여 **스프링 컨테이너(IoC 컨테이너)** 에 등록합니다.
##### 3단계: 프록시(Proxy) 객체를 통한 기능 주입
가장 중요한 부분입니다. `@Transactional`이나 `@Async` 같은 어노테이션은 원본 코드에 없는 기능을 추가해야 합니다. 이때 스프링은 **프록시 패턴**을 사용합니다.
- 사용자가 메서드를 호출하면, 원본 객체가 아닌 스프링이 만든 **가짜 객체(Proxy)** 가 대신 호출됩니다
- 이 프록시 객체가 "트랜잭션 시작 -> 실제 메서드 실행 -> 트랜잭션 커밋"과 같은 부가 기능을 수행합니다.
