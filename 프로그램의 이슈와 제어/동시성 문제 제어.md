## 동시성 제어
동시성 제어는 **여러 트랜잭션이 동시에 같은 데이터에 접근할 때 데이터 정합성과 일관성을 보장하기 위한 제어 기법**입니다. 동시성 제어가 없으면 데이터가 덮어써지거나, 잘못된 값이 저장되는 문제가 발생할 수 있습니다.

## 동시성 문제 발생
동시성 문제는 주로 "여러 작업 주체(쓰레드/프로세스)가 공유 자원에 동시에 접근하여 수정할 때"발생


## 동시성 문제가 발생하는 지점 파악하기
1. 공유 자원 확인: 여러 스레드가 동시에 접근하는 변수(static 변수, 싱글톤객체의 필드), 데이터베이스의 동일한 레코드(row), 로컬 서버의 파일이나 캐시 데이터
2. 상태 변경 확인: 단순히 읽기만 하는 곳은 문제가 없다. 데이터를 읽고->수정하고->저장 하는 '비즈니스 로직'이 포함된 구간이 위험 구간이다.
3. 원자성이 깨지는 구간 확인: 예: "재고 확인(10개 있음)" -> "주문 처리" -> "재고 업데이트(9개로)"
	위 과정 사이의 찰나에 다른 스레드가 "재고 확인"을 해버리면 둘 다 10개라고 판단하게 됩니다. 이를 Lost Update(두 번째 수정이 첫 번째 수정을 덮어씀)현상이라고 합니다.


## 동시성 문제 해결 전략
해결 방법은 크게 **애플리케이션 단, DB 단, 아키텍처 단** 세 가지로 나뉩니다.

1) 애플리케이션 레벨(자바 기준)
	- synchronized 키워드: 가장 간단하지만, 서버가 여러 대인 분산 환경에서는 무용지물이며 성능 저하가 크다
	- Concurrent 패키지: `ConcurrentHashMap`, `AtomicInteger` 등 자바가 제공하는 **동시성 보장 컬렉션**을 사용합니다. (단일 서버 내 변수 제어에 유용)
	
2) 데이터베이스 레벨(가장 많이 사용) > [[Lock의 종류]] 참고
	- 비관적 락(Pessimistic Lock)
		-동시 수정이 발생할 가능성이 높다고 가정하고 데이터를 조회할 때부터 락을 걸어 다른 트랜잭션의 접근을 차단하는 방식 (락이 해제될 때까지 다른 트랜잭션은 대기한다.) 
		성능저하를 고려해 락 범위를 최소화하기도 한다.
		-JPA 에서는 `SELECT ... FOR UPDATE` 형태로 사용
		-장점 : 확실한 정합성을 보장
		-단점 : 대기 시간 증가로 성능저하, [[데드락(Deadlock, 교착 상태)|데드락]] 위험
	- 낙관적 락(Optimistic Lock)
		-동시 수정이 자주 발생하지 않는다는 가정 하에 데이터를 수정할 때만 충돌 여부를 검사하는 방식
		-`@Version` 컬럼을 두고 업데이트 시점에 버전을 비교해서 값이 다르면 예외를 발생시켜 충돌을 감지
		-장점 : DB락을 잡지 않아 성능이 좋음
		-단점 : 충돌 시 재시도 로직이 필요함

3) 분산/아키텍처 레벨(대규모 시스템)
	- 분산 락(Distributed Lock) : Redis(Redisson 라이브러리)나 Zookeeper를 사용하여 여러 서버 간의 공통된 락을 관리합니다.
	- 메시지 큐(Message Queue) : Kafka나 RabbitMQ를 사용하여 요청을 한 줄로 세웁니다(Sequential Processing). DB에 접근하는 프로세스를 하나로 제한하여 원천적으로 동시성을 차단합니다.


## 동시성 문제가 발생한다면 어떻게 해결할 것인가?
> "먼저 해당 로직의 **충돌 빈도**와 **데이터의 중요도**를 따져보겠습니다.
> 
> 1. 사용자 프로필 수정처럼 충돌이 드물다면 **낙관적 락**으로 성능을 챙기겠습니다.
>
> 2. 하지만 결제나 재고 관리처럼 데이터 정합성이 필수적이고 충돌이 잦다면 **비관적 락**이나 **Redis를 활용한 분산 락**을 사용하여 데이터 무결성을 최우선으로 확보하겠습니다.
>     
> 3. 만약 처리량이 너무 많아 DB 부하가 우려된다면, **메시지 큐**를 도입해 요청을 순차적으로 처리하는 비동기 방식을 고려하겠습니다."



## 동시성 제어해본 경험이 있나요?

(실제 경험 없음)

실제 운영에서 직접 해결한 경험은 없지만, 동일한 문제가 발생할 수 있는 구조를 인지하고 있었고, 그런 경우 낙관적락이나 비관적 락을 통해 어떻게 해결할지에 대해서는 학습하고 있습니다.
